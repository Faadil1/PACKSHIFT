# PACKSHIFT — Living PRD v0.2

## North Star
**You don't watch the rules change. You watch the package make room for them.**

PACKSHIFT turns packaging constraints into visible spatial cause-and-effect.

## Thesis
**Packaging is not a file. It is a compiled surface.**

## Problem
Packaging teams reconcile market, language, regulatory, sustainability, and brand requirements across many variants. Traditional workflows expose the result as files, comments, versions, and approvals. They rarely make the spatial consequence of each requirement understandable at a glance.

## Locked mechanism
`CONSTRAINT → PRESSURE → COLLISION → REFLOW → VALID FORM`

Requirements enter the scene as physical demands on a finite package surface.

## V2 structural direction
The package itself is the interface.

- No permanent dashboard sidebars.
- No hero percentages.
- No giant diagnostic force panels.
- Package occupies roughly 60–70% of the visual field.
- Constraints enter as physical content blocks.
- Collision must be visible as overlapping/competing surface occupation.
- **COMPILE** must visibly open the package into a living dieline, move content, rebalance hierarchy, and refold the same object.

## Primary user / JTBD
Packaging designer or artwork operations lead:

> “When a market requirement or claim changes, show me what it physically displaces and how the same master package can reflow.”

## Hero sequence
1. **ONE MASTER** — one calm carton.
2. **LANGUAGE ENTERS** — FR/EN copy consumes width.
3. **DATA CLAIMS A FACE** — the data carrier requires actual surface.
4. **CLAIM DOES NOT FIT** — 24H HYDRATION collides with existing front-panel hierarchy.
5. **COMPILE** — carton opens into its dieline.
6. **REFLOW** — content migrates and hierarchy changes.
7. **REFOLD** — dieline becomes the carton again.
8. **VALID FORM** — the object becomes calm.
9. **EU → CANADA** — same master recompiles for another market.

## MUST
- One physical package remains the center of the experience.
- The collision is understandable without explanatory documentation.
- Compile visibly transforms geometry, not only metadata.
- Dieline opening and refolding are part of the causal explanation.
- EU/Canada switch reuses the same master object.
- Manual controls remain available for judges/operators.
- 15-second deterministic demo remains available.
- Responsive from 360px upward.
- `prefers-reduced-motion` fallback preserves state clarity.

## MUST NOT
- Become dashboard-first SaaS.
- Use chatbot interaction.
- Use certificate / receipt / proof-badge mechanics.
- Imply legal compliance.
- Use dark neon AI-product styling as the primary visual language.
- Treat “valid form” as regulatory validation.

## Visual system
**Editorial print lab × industrial dieline system**

- warm ivory substrate
- black print ink
- registration red for conflict
- restrained technical blue for data
- real paper/cardboard material cues
- sparse UI chrome
- typography and dieline geometry carry the experience

## Motion grammar
Motion must have a job.

- language enters → shows width pressure
- data enters → shows face ownership
- collision compresses → shows competition
- dieline opens → shows available geometry
- content moves → shows resolution
- refold calms → shows valid form

## NFRs
- fast first paint
- keyboard-accessible buttons
- responsive layout
- reduced-motion support
- no external runtime dependencies
- deterministic build

## Truth boundary
Current prototype uses deterministic demo rules. “VALID FORM” means the V2 interaction has resolved its own demo constraints. It is **not** a legal or regulatory compliance determination.

## Acceptance criteria
- The package visually dominates the first screen.
- Adding FR/EN visibly changes the package hierarchy.
- Adding DATA CARRIER visibly occupies a physical package face.
- Adding 24H HYDRATION creates a visible collision.
- COMPILE unfolds the carton into a dieline before resolution.
- Content visibly changes placement/scale during compile.
- The carton refolds into a calmer final state.
- EU → Canada recompiles the same package.
- Production build passes.
- Live desktop/mobile runtime is visually reviewed before PR promotion.
