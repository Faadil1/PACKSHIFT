# PACKSHIFT V3 — Three.js Spatial Compiler Plan

## Purpose

V3 exists to test one question:

**Does real 3D geometry make PACKSHIFT's core mechanism materially clearer and more memorable?**

This branch is not a cosmetic 3D pass. Three.js is only justified if it makes the package's finite surfaces, unfolding, content movement, and refolding easier to understand.

## Stack

- React
- Vite
- Three.js
- React Three Fiber
- Drei
- GSAP

## Architectural rule

**3D for product physics. DOM for controls.**

### 3D owns
- carton geometry
- independent package faces
- camera
- lighting
- paper material
- folded state
- dieline state
- unfold/refold motion
- later: spatial constraint objects and collision markers

### DOM owns
- title / thesis
- market controls
- operator controls
- status text
- accessibility and fallback UI

## Phase A — Spatial proof

Build only:
1. six-face carton
2. physically plausible folded state
3. coherent dieline layout
4. GSAP unfold
5. GSAP refold
6. artwork anchored to surfaces
7. EU/Canada proof copy

**Gate:** visual review must show that 3D is load-bearing.

## Phase B — Constraint anchoring

After Phase A passes:
- FR/EN enters toward copy surface
- data carrier owns the data face
- 24H HYDRATION competes for front-panel territory
- collision marker exists in package space

## Phase C — Real compile

During unfold:
- front claim can reduce or migrate
- copy can move toward back/side
- data module can settle on side face
- hierarchy visibly rebalances

Then refold the same master.

## Phase D — Cinematic demo

Final sequence:

MASTER -> LANGUAGE -> DATA -> CLAIM -> COLLISION -> UNFOLD -> REFLOW -> REFOLD -> VALID FORM -> MARKET SWITCH

Use camera movement only to improve causality.

## Motion rules

Every motion must serve at least one:
- causality
- orientation
- hierarchy
- spatial understanding
- feedback

No idle spectacle beyond restrained product float.

## Promotion gate

Do not merge V3 into the V2 branch unless:
- Three.js improves comprehension
- dieline transition is visually convincing
- desktop performance is acceptable
- mobile has a deliberate simplified framing
- reduced-motion remains understandable
- no truth-boundary regression occurs
