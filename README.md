# PACKSHIFT — Day 19

**Packaging is not a file. It is a compiled surface.**

PACKSHIFT is an interaction study for packaging teams working across markets, languages, regulatory requirements, and brand claims. Instead of treating variants as separate files, the prototype makes constraints visible as spatial forces on one package.

## Interaction signature

`CONSTRAINT → PRESSURE → COLLISION → REFLOW → VALID FORM`

## Vertical slice

- EU / Canada market switching
- Bilingual language pressure
- Data-carrier / recycling requirement
- Marketing claim collision
- Surface-pressure meter
- Compile / reflow state
- 15-second deterministic demo sequence
- Responsive layout and reduced-motion support

## Run

```bash
npm install
npm run dev
```

Production build:

```bash
npm run build
```

## Truth boundary

This is a **concept prototype**, not a regulatory compliance engine. The rule weights and validation state are deterministic demo logic used to communicate the interaction model; they are not legal advice or production compliance checks.

## Day 19 thesis

The novel mechanism is not automated artwork generation. Existing tools already automate templating, localization, and variants. PACKSHIFT explores a different interaction model: **regulatory and content requirements behave like physical forces that consume and reshape packaging surface area.**
