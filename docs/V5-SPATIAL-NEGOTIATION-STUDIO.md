# PACKSHIFT V5 — Spatial Negotiation Studio

## Why V5 exists

V4 proved the remote Blender → GLB → React Three Fiber pipeline, but the experience was still too simple:

- Blender was visible mostly as “a better box”.
- decomposition was too shallow;
- user agency was limited to buttons;
- surface pressure was explained more than experienced;
- the experience lacked a strong memory hook.

V5 changes the product from a **3D packaging demo** into a **spatial negotiation studio**.

## North Star

**You don't watch the rules change. You watch the package make room for them.**

## Signature interaction

The user can:

1. orbit the package freely;
2. drag requirements directly in 3D;
3. drop them onto real Blender-authored package faces;
4. overload a surface and create a real pressure state;
5. scrub the package apart from closed form to internals to shell to dieline;
6. inspect X-Ray and Pressure views;
7. manually move constraints to resolve trade-offs;
8. invoke COMPILE to watch the object open, reflow requirements, and refold.

## Memory hook — Impossible Front

The signature demo deliberately puts:

- FR / EN
- DATA CARRIER
- 24H HYDRATION

all onto the front panel.

The front becomes over capacity.

The package visibly refuses the brief.

Then COMPILE:
- opens the physical product architecture;
- reveals jar, cap, seal, insert and leaflet;
- unfolds the carton;
- exposes the full dieline;
- redistributes information;
- refolds into a calm valid form.

The transformation is now both **physical** and **informational**.

## Interaction model

### Orbit
Pointer drag on empty space.

### Spatial constraint placement
The three requirement cards are real R3F objects.

Drag a requirement over the package.

Raycasting identifies the Blender-authored face under the pointer.

Release to place the requirement.

### Decomposition scrubber

0% — CLOSED  
~30% — INTERNAL PRODUCT  
~60% — SHELL / EXPLODED  
100% — DIELINE

The scrubber directly manipulates the Blender hierarchy.

### Views

**PACK**  
Normal physical package.

**EXPLODED**  
Product architecture + opening shell.

**DIELINE**  
Maximum fold exposure.

**X-RAY**  
Outer shell becomes translucent; internals remain visible.

**PRESSURE**  
Surface materials and labels expose demand/capacity.

## Pressure model

The current capacity system is deterministic concept logic, not regulatory logic.

It exists to demonstrate trade-offs.

A collision occurs when accumulated requirement weight exceeds a surface's demo capacity.

The user can solve the collision manually by dragging a requirement to another face.

## Compile behavior

COMPILE is no longer the primary interaction. It is the **system response** after the user has created a state.

Sequence:

`CURRENT FORM → OPEN → PHYSICAL DECOMPOSITION → DIELINE → REFLOW → REFOLD → VALID FORM`

## Truth boundaries

- Blender geometry is concept engineering, not manufacturing CAD.
- surface capacities are demo rules, not legal/regulatory rules.
- VALID FORM means internally resolved PACKSHIFT state only.
- GLB build proof is not live browser behavior proof.
- cinematic quality cannot replace product mechanism clarity.

## Promotion gate

V5 cannot replace V4 until live QA proves:

- drag-to-surface works reliably;
- orbit remains usable;
- decomposition scrubber is coherent;
- internal product components separate legibly;
- glue/dust flaps improve understanding;
- X-Ray is materially useful;
- Pressure mode makes trade-offs legible;
- Impossible Front is immediately understandable;
- COMPILE feels like a memorable transformation;
- mobile has a deliberate interaction model;
- reduced-motion remains understandable;
- frame rate is acceptable.
